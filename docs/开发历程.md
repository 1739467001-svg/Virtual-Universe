# 虚拟宇宙（Virtual Universe）开发历程

> 一份按时间线整理的项目协作记录 —— 记录这个基于 Three.js 的太阳系漫游 Web 应用，
> 是如何在人与 AI（Claude Code）的一轮轮对话中，从一个雏形逐步打磨成型的。
>
> 每一节包含：**需求 → 遇到的问题 → 解决方案 → 结果**，方便他人清晰地看到完整的演进过程。

---

## 项目概览

- **是什么**：浏览器里的太阳系模拟与漫游。八大行星 + 矮行星、卫星、彗星、流星雨、小行星带；
  真实自转轴倾角与真实星历对齐；自由飞行（飞船视角）、一键飞抵、自动语音导览、VR 支持。
- **技术栈**：纯静态站点 + [Three.js](https://threejs.org/)（已 vendor 进仓库，离线可用，无需构建）、
  Web Audio（程序化背景音乐）、Web Speech（语音解说）、WebXR（VR）。
- **工程化**：GitHub Actions + Playwright 三端（电脑/平板/手机）自动化测试，每次推送自动跑、出截图。

---

## 时间线

### 阶段 0 · 起点（早期基线）

项目最初已有几轮迭代，奠定了基础能力：

1. **自由飞行（飞船视角）** —— 第一人称漫游，WASD/QE 移动、鼠标转向。
2. **真实感升级** —— 真实行星贴图、Bloom 辉光、银河天空盒、太阳日冕。
3. **沉浸飞行** —— 一键飞抵行星、仪表盘 HUD、小地图雷达、碰撞/自动减速。
4. **丰富天体** —— 彗星（掠日拖尾）、流星雨、矮行星、卫星、真实星历对齐。
5. **自动导览 + 语音解说** —— 依次飞向每颗行星并朗读简介。

> 以下是本轮协作中逐步完成的内容。

---

### 阶段 1 · 导览体验打磨

**需求**：导览模式希望更直观。

- **字幕条 + 进度条**：屏幕底部显示当前天体解说字幕，与语音同步；顶部「第 N / 9 站」进度。
- **播放控制**：上一站 / 下一站 / 暂停讲解（暂停时语音同步暂停）。
- **环绕镜头**：每站抵达后相机缓慢绕行星环绕，展示感更强。

---

### 阶段 2 · 性能与多端适配

**需求**：希望整体更流畅、不卡顿，并适配手机/平板/电脑。

- **自适应分辨率**：按帧率动态升降像素比 —— 掉帧时降分辨率保流畅，帧率宽裕时回升保清晰；
  移动端关闭 MSAA、降低像素比上限。
- **移动端响应式布局**：控制面板顶部换行、按钮加大；信息卡改底部抽屉；导览条适配刘海安全区。

---

### 阶段 3 · 多端实测与抓 bug

**需求**：在电脑/平板/手机上实测抓 bug。

**遇到的限制**：远程环境**装不了浏览器**（网络策略屏蔽了下载），WebGL 也无法在无头环境运行。

**解决方案**：先做能自动化的检查 + 设备级代码审计，抓到并修复 3 个真实 bug：

1. **刘海屏安全区失效** —— CSS 用了 `env(safe-area-inset-*)` 但 viewport 缺 `viewport-fit=cover`。
2. **触屏上「自由飞行」是死状态** —— 它依赖指针锁定 + 键盘，手机上无法操作 → 触屏隐藏该按钮。
3. **移动端控制面板可能占满屏** —— 限高可滚动。

---

### 阶段 4 · 引入持续集成（CI）

**需求**：既然本地测不了，就让云端替我们在真浏览器里测三种设备。

**方案**：搭建 **GitHub Actions + Playwright** 流水线：

- 每次 push / PR 自动触发；
- 用 Chromium 模拟 **电脑 / 平板 / 手机** 三套视口（`isMobile` + `hasTouch` 触发移动端代码路径）；
- 监听控制台报错 + 关键交互断言 + **自动截图**，产物上传留存。

并产出一份**可复用的测试方案文档**（`docs/ci-multi-device-testing.md`），含原理讲解与可直接套用的模板。

> 💡 这一步意义重大：之后多次本地 `node --check` 没抓到、CI 在真实浏览器里抓到的问题，都靠它兜住。

---

### 阶段 5 · 画质升级：木星与大红斑

**需求**：特别喜欢木星和它的「风暴之眼」（大红斑），希望画质升级。

- **气态巨行星动态大气层**：半透明云带叠层，随本体略有速度差缓慢漂移，营造云带流动、风暴翻涌感。
- **大红斑涡旋**：在木星表面叠加一个会就地自旋的涡旋。
- **精准对齐**：没有去找外部模型，而是**直接读取仓库里的 `jupiter.jpg` 贴图**，
  肉眼定位大红斑在图中的位置（水平 22.5% / 垂直 62.5%），按球体 UV→经纬度公式换算出
  `经度 99° / 纬度 −22.5°`，让涡旋正好盖在烘焙的红斑上。

---

### 阶段 6 · 速度系统重构

**需求 / 问题**：「为什么每个星体自转特别快？」

**诊断**：默认速度 60 = 每秒模拟 60 天，而自转周期才 0.4~1 天 → 木星每秒自转上百圈。
根因是**自转和公转共用同一个时间倍率**，但两者时间尺度差上百倍。

**演进**（用户连续反馈，逐步逼近理想）：

1. 默认速度 60 → 15，并加自转柔化系数。（仍偏快）
2. **自转与时间倍率彻底解耦** —— 自转改用独立的观察友好慢速（地球约 30 秒一圈），
   速度滑块只驱动公转；保留行星间相对快慢（木星快、金星几乎不动、逆向自转）。
3. **可点速度档位**（1/2/5/10/20/50×），点击即切换、滑块与数字同步。
4. **自转 / 公转分开控制** —— 各一套滑块 + 档位，互不影响。

---

### 阶段 7 · 控制面板可折叠

**需求**：面板控制项变多，希望能收起。

- **速度面板折叠**：单独折叠「公转 / 自转」两行。
- **整个面板总收起按钮**：右上角 −/＋，一键收起，腾出观察空间。

---

### 阶段 8 · 背景音乐

**需求**：进入太阳系后加一段符合主题的纯音乐。

**限制**：下载不了音频素材，也不该打包有版权的音乐。

**方案**：用 **Web Audio 程序化生成**太空氛围音乐（零素材、离线、无版权）：
暖色合成器铺底 + 五声音阶随机点缀音粒 + 反馈延迟空间感。

**扩展**：

- **音量滑块**（实时调节）。
- **三种氛围**：🌌 深空（低沉）/ 🎵 默认 / 🚀 星际旅行（明亮），切换时平滑过渡不断音。

---

### 阶段 9 · 全设备自适应增强 + 设置持久化

- **设备感知默认布局**：小屏/触屏**默认收起**面板，进入即清爽；平板半宽、横屏、超窄屏专项布局。
- **设置持久化（localStorage）**：记住公转/自转速度、音乐开关/音量/氛围、轨道线/标签/语音、面板折叠态，刷新后保持。

**这一阶段的 CI 排错链**（很能说明 CI 的价值）：

1. `run #16` —— 测试文件**注释与 `test()` 粘连**导致解析失败（本地 `node --check` 漏掉，CI 的 babel 抓到）。
2. `run #18` —— 移动端**速度子面板未展开**，档位按钮不可见 → 测试先展开再操作。
3. `run #19` ✅ —— 持久化从「事件委托 + setTimeout」改为**各 setter 内显式同步保存**（原方案在点击后刷新前可能未写入），并加 `localStorage` 诊断断言，最终三端九项全绿。

---

### 阶段 10 · 语音导览修复

**问题**：「语音导览为什么只讲解太阳？」期望是靠近星体就自动讲解。

**根因**：`speechSynthesis.cancel()` 紧接 `speak()` 触发 Chrome 经典竞态 —— 异步的 `cancel()`
会把刚排进去的新语音也取消。第一站（太阳）队列为空所以能播，之后每站都被顺手杀掉。

**方案**（逐步加固）：

1. `cancel()` 后延一拍再 `speak()`，并保留 utterance 引用防 GC。
2. **显式选中文嗓音** + 监听 `voiceschanged` + 定期 `resume()` 保活（治 Chrome「只响一句 / 中途停」）。
3. **推进不再依赖可能不触发的 `onend`**，改为**按文本长度估算解说时长**来停留（确定性，绝不卡在太阳）。
4. **接近自动解说**：自由飞行靠近某天体时自动播报（滞回触发，换天体才念）。

## 工程方法论小结（这次协作的几条经验）

1. **环境受限就换打法**：装不了浏览器 → 把测试搬到云端 CI；下不了音频 → 程序化生成音乐；
   找不到红斑模型 → 直接读贴图定位。约束催生更稳的方案。
2. **CI 是真正的安全网**：多次本地静态检查漏掉、真实浏览器才暴露的问题，都靠三端自动化测试兜住。
3. **小步快跑、即时反馈**：每个需求独立成 commit，推送即跑 CI，绿了再继续。
4. **诚实面对不确定**：看不到渲染结果时（如红斑对齐），明确说明依据与残余风险，并留好可微调的参数与注释。
5. **根因优先**：自转太快、语音只念太阳，都不是表面调参，而是定位到「倍率耦合」「cancel 竞态」等根本原因再修。
